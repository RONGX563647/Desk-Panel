Product Requirements Document

Desk Panel 产品需求文档

把闲置手机或平板变成电脑的桌面状态屏与快捷控制面板：不装 App、不登录云账号， 在局域网内用浏览器打开即可查看系统状态并触发受限操作。

版本 v0.2 草案 日期 2026-11-17 对应代码 v0.1.0 文档类型 常规 PRD 适用范围 P0 / P1 / P2

01文档说明

定义产品行为与业务规则，不约束技术实现。

本文档面向产品、设计与开发三方，用于对齐 Desk Panel 的边界、核心流程与功能规则。 文中“已实现 / 部分实现 / 未实现”基于对当前仓库代码的实际检查，仅用于现状对照； 功能需求部分描述的是目标行为，不代表现有能力。

项目内容
产品名称Desk Panel（桌面面板）
产品形态PC 端本地代理 + 浏览器端全屏面板（PWA 可添加到主屏）
核心用户拥有闲置手机/平板、希望随时查看或轻控制电脑的个人用户
使用环境家庭或办公室局域网；PC 与手机处于同一网络
不在本文档范围技术架构、接口设计、数据库设计、排期与人力计划

优先级定义

级别含义纳入判断
P0可用闭环缺失时产品无法完成“打开面板 → 看到状态 → 执行动作”的最小旅程，或存在明显安全缺口。
P1日常可用缺失时产品仍能用，但需要频繁回到电脑操作，无法长期替代桌面小屏。
P2扩展能力提升上限或覆盖特定场景，可在核心体验稳定后评估。

02项目现状分析

基于当前代码与构建产物的实际检查，不包含推测性功能。

整体阶段
可演示 MVP 核心闭环已跑通

启动服务、浏览器访问、实时指标、快捷动作、断线重连均已可用；产品化程度约为 P0+P1 功能面的三成（产品判断，非精确度量）。

最大短板
安全模型 与可配置性

当前为“局域网监听 + 可选共享 token”，缺少设备配对、传输加密与动作确认；布局和动作均写死在代码里。

已具备能力

能力域状态现状说明
服务与构建已实现Node 服务同时提供 API、WebSocket 与构建后静态页面；开发态前后端双进程启动。
实时指标通道已实现WebSocket 长连接，约 1 秒推送一次；连接建立即下发当前快照。
CPU / 内存 / 运行时长已实现CPU 按核心计算差值并展示分核柱状；内存展示已用与总量；运行时长按小时取整。
磁盘部分实现仅统计系统盘 C:，多盘与容量趋势未覆盖。
网络速率部分实现取首个活动网卡计算上下行速率，约 3 秒采样；无累计流量与多网卡切换。
时钟与日期已实现秒级刷新，展示年月日与星期。
快捷动作部分实现终端、文件管理器、VS Code、浏览器、锁屏共 5 个固定动作；仅 Windows 可用，浏览器地址写死，失败反馈不准确。
访问鉴权部分实现可选共享 token，支持查询参数或请求头；未设置 token 时对局域网完全开放；无配对、无设备身份、无限流、无传输加密。
断线恢复已实现指数退避重连（上限约 8 秒），离线时显示遮罩并保留最后数据。
移动端 / PWA部分实现具备 manifest、图标、全屏与屏幕常亮；无 Service Worker、无离线壳、无安装引导。
响应式布局部分实现横屏 12×6 固定网格，竖屏单列固定顺序；不可增删组件、不可拖拽、不可多页。
配置与运行管理未实现无设置界面、无配置持久化、无托盘、无开机自启、无日志查看。
媒体 / 通知 / 文件 / 剪贴板未实现均未覆盖。
自动化 / 自定义动作未实现动作白名单写死在服务端，用户无法新增应用、网址或组合键。
工程质量缺失无版本库、无测试、无 CI、无错误日志与使用文档。

关键判断：当前最大的风险不是“功能少”，而是局域网内任意设备在未设置 token 时可直接读取主机信息并触发本机程序。安全模型必须先于功能扩展补齐。

当前实现中的具体问题

  • 动作执行采用“启动后固定等待 120ms 即返回成功”，程序不存在或无权限时仍可能提示成功。
  • 浏览器动作固定打开 GitHub，不是用户可配置的入口；无法作为常用网站快捷方式。
  • token 通过 URL 查询参数传递，容易进入历史记录、截图和日志；未启用 HTTPS 时在局域网明文传输。
  • 磁盘路径、动作列表、端口等均硬编码，修改需要改代码并重启。
  • CPU 首次采样因缺少上一次快照而显示 0，容易被误读为真实负载。

03同类项目参考

只借鉴与产品决策相关的能力与边界，不复制其功能数量。

PhoneBox（ersinkoc/phonebox，MIT）

与本项目定位最接近：把闲置 Android 手机变成电脑的桌面面板。由 PC 端代理采集数据， 手机端为全屏 App，通过 USB（adb reverse）或配对后的 Wi-Fi 连接；PC 端提供浏览器可视化编辑器， 支持 12×6 栅格、多页面、模板与组件拖拽。

  • 能力范围：CPU、GPU、内存、多磁盘、网络与 ping；应用/网址/组合键/宏；媒体、音量、OBS；天气、日历、待办、番茄钟；Webhook、Home Assistant、规则触发切页；AI 编码会话与配额。
  • 安全模型：代理仅监听 127.0.0.1，USB 通过 adb 反向隧道访问；Wi-Fi 使用 HTTPS、证书固定与配对密钥；手机只能提交动作 ID，命令与凭据留在电脑。
  • 启示：“动作 ID 白名单”是正确的边界设计；但 Android App + USB 调试的安装门槛较高，浏览器零安装是本项目可以坚持的差异点。

04目标与成功标准

用可观察的行为描述结果，不使用无法验证的体验口号。

编号目标可观察的成功标准
G-1开箱即用新用户在 PC 端启动程序后，2 分钟内完成扫码配对并在手机上看到实时状态，无需安装手机 App。
G-2状态可信面板数值与系统实际状态一致；无法采集的指标显示“--”与原因，不以 0 代替。
G-3操作有反馈每次动作点击后 300ms 内出现“处理中”，并在 2 秒内给出成功或失败原因；不存在静默失败。
G-4断线可自愈手机锁屏、切后台或短暂断网后回到页面，5 秒内恢复数据，且无需重新配对。
G-5默认安全未配对设备无法读取主机名、系统指标或动作列表，也无法触发任何动作。
G-6可长期摆放手机横竖屏均完整显示且无横向滚动；可添加到主屏并以全屏方式运行。

05用户与核心旅程

单一角色场景，但同时存在“使用者”和“本机管理员”两种操作位置。

角色

角色操作位置职责
面板使用者手机 / 平板浏览器查看状态、切换页面、触发已配置的动作。
本机管理员PC 本机浏览器 / 托盘启动与停止服务、生成配对码、管理设备、配置动作与布局。

说明：两种角色默认是同一自然人。管理员能力只能在本机访问，手机端不具备配置权限。

P0 核心旅程

PC 启动代理→ 显示地址与二维码→ 手机扫码→ 输入配对码→ 查看实时状态→ 触发动作→ 获得结果反馈
  • 触发：用户坐到桌前，希望用闲置手机常亮显示电脑状态，或离开时快速锁屏。
  • 完成条件：手机端看到至少一项实时指标，并成功执行一次动作且收到明确反馈。
  • 恢复路径：断网或 PC 休眠后，页面自动重连；重连失败时给出“检查 PC 端是否运行”的明确提示。

P1 日常旅程

  • 用户把常用应用、网址配置成动作，按“工作 / 娱乐”分成两页，左右滑动切换。
  • 用户在手机上控制媒体播放与音量，不必切回电脑。
  • 用户将面板添加到主屏，锁屏后重新点亮即可看到最新状态。

06范围与优先级

先完成可用的最小闭环，再补日常高频能力，最后评估扩展。

优先级能力纳入理由
P0启动与访问入口用户必须先知道在哪里打开面板，二维码与地址展示是零安装体验的起点。
P0设备配对与撤销控制的是真实电脑，默认拒绝未授权设备是产品成立的前提。
P0连接状态与自动重连移动端锁屏、切网频繁，不能要求用户手动刷新。
P0系统状态总览面板的核心价值，构成“看一眼就知道电脑怎么样”的闭环。
P0时钟与日期常亮摆放时的基础信息，成本低且高频使用。
P0快捷动作从“看”到“用”的关键一步，验证动作白名单模型。
P1动作自定义固定动作无法覆盖个人工作流，是长期留存的分水岭。
P1布局与多页面不同设备的屏幕尺寸与使用场景差异大，固定布局很快触顶。
P1媒体与音量桌面场景高频控制，能显著提升“面板常驻”的价值。
P1移动端与 PWA 完善决定产品是“网页”还是“桌面设备”，影响常亮与全屏体验。
P1设置与运行管理端口、设备、自启、日志需要可视化，否则只能改代码。
P2通知 / 剪贴板 / 文件价值明确但依赖平台权限，先保证核心稳定。
P2自动化与 Webhook面向进阶用户，需要完善的动作安全分级支撑。
P2AI 编码会话参考 PhoneBox 的差异化能力，依赖本地 CLI 集成，非通用需求。

07功能需求

每个模块描述触发条件、处理规则、结果与异常，避免只列功能名。

FR-01

启动与访问入口

P0 部分实现

目的

让用户不必查找 IP 地址，就能在手机浏览器打开面板。

触发

管理员在 PC 端启动代理服务。

处理规则

  • 启动后在控制台或托盘展示：本机访问地址、局域网访问地址、二维码、当前端口与运行状态。
  • 二维码只包含访问地址与一次性配对入口，不得包含长期有效的密钥。
  • 服务默认监听局域网；设置页仅允许本机访问。
  • 端口被占用时，启动失败并提示具体端口；P1 支持自动推荐可用端口。
  • 未检测到可用局域网地址时，提示“仅本机可访问”。

结果与状态

管理员看到可直接扫描的入口；手机打开后进入配对页，而不是直接进入面板。

异常

  • 系统防火墙拦截：提示需要放行的端口与网络类型，并给出检查步骤。
  • PC 休眠或服务退出：手机端显示离线遮罩，服务恢复后自动重连。
FR-02

设备配对与撤销

P0 未实现

目的

把“局域网内任何人可访问”收敛为“只有管理员授权的设备可访问”。

触发

首次访问、配对码过期、管理员主动撤销设备。

处理规则

  • 管理员在本机生成一次性配对码，有效期 5 分钟，成功使用一次后立即失效。
  • 手机提交配对码，并附带设备名称与设备类型；管理员在本机确认后，该设备获得访问凭证。
  • 凭证保存在手机本地，后续访问不再要求输入配对码。
  • 默认最多允许 5 台设备，管理员可在设备列表中查看名称、最近在线时间并撤销。
  • 撤销后，该设备的下一次请求立即失效；已建立的长连接在 10 秒内断开。

结果与状态

未配对设备只能看到配对页，无法获取主机名、系统指标、动作列表或页面布局。

状态未配对→ 状态配对中→ 状态已配对→ 状态已撤销

异常

  • 配对码错误连续 5 次：该来源地址锁定 10 分钟，并提示稍后重试。
  • 配对码过期：明确提示“配对码已失效”，并提供重新生成入口。
  • 设备被撤销：手机端显示“已被移除此电脑”，仅保留重新配对入口。
  • 超过设备上限：提示管理员先撤销不用的设备，不允许静默替换。
FR-03

连接状态与自动重连

P0 已实现

目的

让面板具备“放在桌上不用管”的稳定性。

状态定义

状态判定条件界面表现
连接中已打开页面，尚未收到首帧数据显示“正在连接电脑…”
在线持续收到数据，间隔不超过 3 秒顶部状态点为绿色
弱网超过 3 秒未收到数据，但未超过 10 秒保留最后数据，标注“数据可能延迟”
离线超过 10 秒未收到数据或连接关闭离线遮罩，展示最后更新时间

处理规则

  • 在线时按 FR-04 的频率刷新；页面进入后台时暂停渲染，但保持连接。
  • 离线后自动重连，间隔从 1 秒递增至最多 8 秒；重连成功即恢复数据。
  • 页面重新可见时立即触发一次重连或刷新，不等待下一次退避。
  • 恢复后不得清空用户当前所在页面与滚动位置。

异常

连续 3 次重连失败时，遮罩中补充排查提示：确认 PC 未休眠、服务仍在运行、手机与 PC 在同一网络。

FR-04

系统状态总览

P0 部分实现

目的

用户扫一眼即可判断电脑是否繁忙、内存是否吃紧、网络是否在传输。

指标范围

指标优先级展示要求
CPU 总负载P0百分比，取最近一个采样区间的平均占用；无数据时显示“--”。
CPU 分核负载P0最多展示 16 个核心的柱状图；超过 16 核时合并或滚动展示。
内存P0已用 / 总量（GB，保留 1 位小数）与使用百分比。
磁盘P0P0 至少展示系统盘；P1 展示所有固定磁盘的已用/总量。
网络速率P0上下行分别展示，单位自动切换 KB/s 与 MB/s；附最近约 30 秒趋势。
运行时长P1展示为“x 天 x 小时”；P0 可仅显示小时。
主机名 / 系统P0顶栏展示主机名；系统版本可在设置或信息区查看。
GPU / 温度 / 进程P1平台支持时展示；不可用时隐藏而不是显示 0。

刷新与精度

  • CPU、内存、磁盘：1 秒一次；网络：2 至 3 秒一次，避免高频采集造成额外负载。
  • 首次连接尚无 CPU 差值时，显示“--”，不得显示 0%。
  • 指标采集失败时保留最近一次有效值，并标注“数据已过期”，超过 30 秒未恢复则清空。

异常

单个指标不可用不影响其他指标展示；不可用项点击后说明原因，例如“当前平台不支持温度读取”。

FR-05

时钟与日期

P0 已实现

规则

  • 展示本地时间（24 小时制）、年月日与星期，秒级刷新。
  • 时间以手机系统时区为准，跨天自动更新日期与星期。
  • 页面从后台恢复时立即校准，不依赖累积计时。

结果

常亮摆放时时间清晰可读；横屏与竖屏均不截断。

FR-06

快捷动作

P0 部分实现

目的

让用户在手机上完成“打开某个程序”或“锁屏”等低风险操作，不必回到电脑。

内置动作

动作风险级别行为与规则
打开终端L2在 PC 上打开系统终端窗口；同一动作 2 秒内只执行一次。
打开文件管理器L2打开用户目录或上次使用的目录。
打开编辑器L2打开已安装的代码编辑器；未安装时明确提示。
打开网址L2P0 使用管理员配置的默认网址；P1 支持多个自定义网址。
锁屏L3锁定当前会话；P0 不需要二次确认，但按钮需与普通动作有明显区分。

处理规则

  • 客户端只提交动作 ID，动作目标与参数由服务端白名单决定，手机端不能提交任意命令。
  • 点击后立即进入“处理中”状态，禁止重复点击；执行完成或超时后给出结果。
  • 动作执行成功以“目标程序已启动/系统已响应”为准，不以“请求已发出”为准。
  • 关机、重启、注销、执行任意命令等 L4 动作不在 P0/P1 开放。

结果与反馈

成功时提示“已执行：动作名”；失败时提示原因与可执行的下一步，例如“未找到 VS Code，请在电脑端检查安装路径”。

异常

  • 程序不存在或无权限：返回明确失败，不得提示成功。
  • 执行超时（默认 5 秒）：提示“已发出但未确认结果”，并允许重试。
  • PC 端处于锁屏或未登录状态：提示需要先解锁电脑。
  • 动作执行期间连接断开：恢复连接后展示最近一次结果，不重复执行。
FR-07

动作自定义与管理

P1 未实现

目的

让面板适配个人工作流，而不是只有开发者预设的 5 个按钮。

可创建的动作类型

类型配置位置配置项
打开应用PC 端设置页名称、可执行文件路径、启动参数、工作目录、图标、是否需确认。
打开网址PC 端设置页名称、URL、图标、是否在首屏。
组合键 / 宏PC 端设置页按键序列、目标窗口条件（P1 可选）、执行间隔。
预设命令PC 端设置页命令、参数、工作目录、超时；仅管理员可编辑，手机端只能触发。

处理规则

  • 动作名称、图标、排序与所在页面可编辑；修改后手机端在一次刷新内生效。
  • 删除动作需要二次确认；删除后手机端对应按钮消失，不保留空位。
  • 目标路径失效时，动作标记为“不可用”，手机端置灰并说明原因。
  • 手机端不得新增、编辑或删除动作，也不得查看完整命令行参数。

异常

命令执行失败时展示退出码与错误摘要（最多 3 行），完整日志仅在 PC 端可查看。

FR-08

页面布局与多页面

P1 部分实现

目的

适配不同尺寸设备与不同使用场景，避免固定布局在手机上过密或浪费空间。

规则

  • 提供默认、监控、控制、极简四种模板；每种模板分别定义横屏与竖屏布局。
  • 使用栅格布局，组件可增删、拖拽与调整大小；组件之间不得重叠。
  • 最多 5 个页面，可重命名与排序；通过左右滑动、页码或音量键切换。
  • 布局默认保存在 PC 端；不同设备可以使用同一套布局，也可单独覆盖。
  • 恢复默认模板需二次确认，且不删除用户自定义动作。

结果与状态

手机端只负责渲染布局，不提供编辑能力；编辑入口只在 PC 本机设置页出现。

异常

  • 组件数据源不可用：保留组件占位并提示原因，不导致整页空白。
  • 布局版本不兼容：回退到默认模板，并保留原布局备份。
FR-09

媒体与音量控制

P1 未实现

目的

覆盖桌面场景最高频的控制需求，让用户不必切回电脑调整播放。

范围

  • 播放 / 暂停、上一首、下一首；当前曲目名称与封面（平台支持时）。
  • 系统音量增加、减少与静音；单次步进 5%。
  • 媒体信息约 2 秒刷新一次；控制指令执行后立即刷新状态。

规则与异常

  • 系统无媒体会话时显示“未在播放”，控制按钮置灰。
  • 平台不支持媒体控制时隐藏整个模块，不展示不可用按钮。
  • 控制失败时提示“当前播放器不支持该操作”，不重复发送指令。
FR-10

移动端体验与 PWA

P1 部分实现

目的

让面板像一台桌面小屏设备一样长期摆放，而不是一个需要反复打开的网页。

规则

  • 支持添加到主屏幕；从主屏启动时以全屏方式打开，隐藏浏览器地址栏。
  • 进入全屏后保持屏幕常亮；浏览器不支持时隐藏“常亮”入口，并说明限制。
  • 适配安全区与刘海屏；横竖屏切换不丢失当前页面与连接。
  • 首次访问时提示“添加到主屏幕”，用户关闭后 7 天内不再重复提示。
  • 离线壳只展示连接状态与最后数据，不缓存主机敏感信息。

异常

  • iOS Safari 不支持全屏 API：退化为普通网页，并提示使用“添加到主屏幕”。
  • 后台被系统冻结：回到前台立即重连并刷新，不展示过期数据超过 10 秒。
FR-11

设置与运行管理

P1 未实现

目的

把端口、设备、动作、布局与启动方式从代码中解放出来，让非开发者也能维护。

范围

  • 服务设置：端口、监听范围、开机自启、托盘运行、更新检查。
  • 设备管理：已配对设备列表、最近在线时间、撤销与重命名。
  • 动作管理：新增、编辑、排序、启用/停用、删除（见 FR-07）。
  • 布局管理：模板选择、页面与组件编辑（见 FR-08）。
  • 诊断信息：版本、运行时长、最近错误日志、当前连接设备数。

权限边界

  • 设置页仅允许本机访问；手机端访问时返回无权限提示，不展示任何配置项。
  • 修改监听端口或撤销设备后，立即提示受影响的连接与新访问地址。

异常

配置文件损坏时自动备份原文件并加载默认配置；日志不得记录配对码、访问凭证或完整命令行。

FR-12

通知、剪贴板与文件

P2 未实现

目的

减少在手机与电脑之间来回切换的成本，覆盖参考项目中的高频互联能力。

范围与规则

  • 通知镜像：可选开启；仅展示应用名、标题与时间，默认不展示正文；手机端可一键清空。
  • 剪贴板：双向同步需手动确认，不自动覆盖；同步内容不落盘。
  • 文件发送：手机上传仅允许保存到管理员指定目录；同名文件自动重命名；单文件大小上限可配置。
  • 文件下载：由 PC 端选择文件后在手机浏览器下载，不提供目录浏览。

异常

传输中断时保留临时文件并允许重试；超出大小或类型限制时在开始前拒绝并说明原因。

FR-13

自动化与 Webhook

P2 未实现

目的

让面板从“固定信息屏”变成能对外部事件做出反应的桌面终端。

规则

  • 支持接收外部 Webhook，更新指定组件的数值或展示一条通知。
  • 支持规则：当满足条件（时间到达、主机空闲、页面切换、外部事件）时切换页面或触发 L2 动作。
  • Webhook 必须使用独立密钥，不得复用设备访问凭证；可随时停用并重新生成。
  • 自动化触发的动作仍受动作分级与确认规则约束，L4 动作不开放。

异常

Webhook 频率过高时按来源限流；规则执行失败时记录日志并在设置页标记最近失败原因。

FR-14

AI 编码会话（可选扩展）

P2 未实现

参考来源

PhoneBox 将 Claude Code、Codex 等本地编码会话的进度、配额与权限请求展示在手机上，形成差异化场景。

若纳入范围，需满足

  • 只读取本地 CLI 已产生的状态，不要求用户提供云端账号或 API 密钥给面板。
  • 权限请求的“允许 / 拒绝”属于 L4 动作，必须二次确认，并明确展示请求来源与命令摘要。
  • 默认关闭，开启前说明会读取哪些本地文件与会话信息。

当前建议：不进入 P0/P1，先观察目标用户是否真的需要把编码会话放到桌面小屏上。

08共享规则

被多个功能引用的规则只在此定义一次。

8.1 动作安全分级

级别示例手机端权限确认要求记录
L1 只读查看指标、时钟、媒体信息已配对设备无需确认不记录
L2 低风险打开应用/网址、切换页面已配对设备无需确认记录动作与结果
L3 中风险锁屏、音量、媒体控制已配对设备可选二次确认记录动作与结果
L4 高风险关机、重启、注销、执行任意命令、删除文件默认不开放二次确认 + 本机确认完整记录
  • 任何新增动作必须先归入某一级别，未分级的动作不得上线。
  • 手机端不能提交命令行、文件路径或任意参数，只能提交动作 ID。
  • L4 动作即使未来开放，也必须同时满足：管理员在 PC 端开启、手机端二次确认、PC 本机确认（或倒计时可取消）。

8.2 访问与鉴权边界

  • 面板数据接口只对已配对设备开放；设置与设备管理只对本机开放。
  • 配对凭证不得出现在 URL 查询参数中；不得写入访问日志、错误日志或前端埋点。
  • 配对码一次性使用、限时有效；配对失败按来源限流。
  • 局域网传输在 P0 至少依赖一次性配对码与短期凭证；P1 评估启用 HTTPS 或等效的加密通道。
  • 公网访问不在产品内实现，推荐使用 Tailscale、ZeroTier 等既有方案，并在文档中明确风险。

8.3 数据刷新与显示口径

数据刷新频率口径
CPU / 内存 / 磁盘1 秒取最近一个采样区间的值；首次采样无差值时显示“--”。
网络速率2–3 秒按字节差除以时间差计算，展示上下行；单位自动切换。
媒体信息2 秒读取系统当前媒体会话；无会话时显示“未在播放”。
设备在线状态连接事件驱动以长连接状态为准，不依赖页面轮询。
时钟1 秒以设备本地时间为准。

8.4 反馈规范

  • 所有用户发起的动作必须经历“处理中 → 成功 / 失败”三态，不允许无反馈。
  • 错误提示必须包含原因与下一步，禁止只显示“操作失败”。
  • 状态不能仅用颜色表达，需同时提供文字或图标。
  • 成功提示默认 2 秒后消失；失败提示保留至用户关闭或重试。

8.5 设备与数据保留

  • 指标数据仅在内存中保留最近一段时间的趋势，不长期落盘。
  • 设备列表保留设备名、类型、配对时间与最近在线时间；撤销后 30 天内可查看历史记录，但不保留访问凭证。
  • 日志默认保留 7 天，按大小滚动；不记录敏感内容。

10非目标与待定

明确不做

  • 远程桌面 / 画面串流：不属于桌面状态屏的定位；需要时使用 RDP、Parsec 或 scrcpy。
  • 公网穿透与云账号：不建设云端中转与账号体系，避免把本地控制面暴露到公网。
  • 手机原生 App：P0/P1 坚持浏览器零安装；是否评估原生壳留待 P2。
  • 跨设备文件同步盘：只做点对点发送，不做持续同步；该场景交给 Syncthing 等工具。
  • 组件数量竞赛：不追求 PhoneBox 级别的组件库，优先保证每个组件的准确性与可用性。
  • 用户行为分析：不接入第三方统计与遥测。
